# Forever 1.60.1 build 70707 — input/identity repair inspection

The requested `_forever_` installation was inspected again through its local CASC data. Active product `wowf`, build 70707, interface target 16001. The existing Camelot visual design is preserved. Inspected native files are fingerprinted in `client-source-manifest.json`; Blizzard code and artwork are not bundled.

## Source-confirmed findings

- `Blizzard_FrameXMLUtil/Camelot/NameUtil.lua` defines `FormatUnitNameForDisplay` and `GetUnmodifiedUnitFullName` by joining `UnitName` / `UnitNameUnmodified` components with `Constants.CharacterNameSeparatorConsts.CHARACTERNAME_SURNAME_SEPARATOR`. Its name splitting function uses that same constant. This Camelot override takes precedence over generic shared behavior. The addon calls those native helpers or implements the same join without imposing a hyphen, and preserves first name/surname.
- `Blizzard_GlueXML/Camelot/CharacterSelect/CharacterSelectList.lua` explicitly identifies the product as having no traditional location-based character addressing. The previous addon identity model was incorrect. GUID is now the preferred ownership key; ruleset plus normalized full name is the fallback.
- The installed executable exports `PvPRuleset` and `RPRuleset`; packed GameRulesDocumentation exposes `C_GameRules.IsGameRuleActive`. The detector uses the corresponding `Enum.GameRule` flags and returns the four supported combinations. Availability/actual running values are printed by diagnostics; no unobserved value is assigned if a flag/API is absent. The executable's symbol inspection establishes presence, not a live API invocation.
- `Blizzard_SharedXML/Shared/InputBox/InputBoxTemplates.xml` provides `InputBoxTemplate`, mouse-enabled scripts, focus highlight/clear behavior and ChatFontNormal. `SimpleEditBoxAPIDocumentation` confirms enabled state, focus methods, text/cursor operations and AltArrowKeyMode. `Blizzard_MoneyFrame/Shared/MoneyInputFrame.xml` uses native edit boxes with numeric entry. The repair keeps InputBoxTemplate and makes enabled mouse/keyboard/focus/font/level behavior explicit for every input, leaving editing keys to the native widget.
- `Blizzard_ItemButton/Mainline/ItemButtonTemplate.lua` defines `HandleModifiedItemClick`: CHATLINK calls **ChatFrameUtil.InsertLink**, checks its boolean return, and stops if consumed. `Blizzard_UIPanels_Game/Mainline/ContainerFrame.lua` routes modified bag clicks through this function and C_Container item links.
- `Blizzard_ChatFrameBase/Mainline/ChatFrameUtilOverrides.lua` implements the current insertion dispatcher for specific focused native inputs, chat and auction search; it does not discover arbitrary addon edit boxes. `Blizzard_DeprecatedChatInfo/Deprecated_ChatFrame.lua` assigns the old `ChatEdit_InsertLink` alias only as a compatibility fallback. Hooking that alias alone does not reliably intercept current bag/item sources.
- A post-hook cannot return the dispatcher's consumed boolean. Version 1.1.1 uses secure post-hooks on the current dispatcher and compatibility alias, accepting only a real item link while the Guild Bounty item edit box is the current keyboard focus, shown, and in an item mode. Native dispatch and return values remain untouched. The 1.1.0 wrapper was removed after a live blocked-action warning; its taint propagation was a plausible cause, not established by the screenshot alone. It does not intercept ordinary bag clicks, dress-up, trade or auction operations.
- `GameCursorDocumentation` exposes `GetCursorInfo` and `ClearCursor`; `CursorDocumentation` exposes C_Cursor.GetCursorItem. A recognized item ID is captured from the cursor tuple, with the ItemLocation route available as fallback. Receiving drop/click handlers are installed on both the item edit field and native item slot. ClearCursor is called only after successfully accepting an item ID. It cancels cursor selection, not ownership of the bag item.
- `ItemDocumentation` confirms C_Item.GetItemInfo's stable ID/link, quality, icon, class/subclass, inventory slot, base item level and required level. Metadata requests are throttled, previews refresh on the item-data/cache events, and unresolved items cannot save. Rule stats not covered by this metadata remain excluded.
- `ChatInfoDocumentation` confirms C_ChatInfo.RegisterAddonMessagePrefix, SendAddonMessage's positional contract, GUILD channel, and CHAT_MSG_ADDON sender fields. GetGuildInfo('player'), IsInGuild, GetNumGuildMembers and GetGuildRosterInfo are used for context and sender roster validation. Full names are preserved; guild roster GUID position 17 supplies actor identity when exposed. Real delivery and ruleset boundaries have not been observed live during this pass. Explicit region/ruleset payload checks supplement the game's guild recipient scope.
- Existing inspected combat documentation exposes restricted standard combat events, an internal event/getter, and secure-only native processing. Version 1.1.1 removes all internal event/getter use and gates standard combat registration on public getter availability and the restriction query. The addon never invokes secure-only facilities; secret or restricted values are skipped. Evidence retains the raw log name strings/GUIDs. Name normalization and identity enrichment are separate operations.

## What caused the old failures, and what remains uncertain

The shift-click defect is directly traceable: the old UI hooked only the deprecated ChatEdit_InsertLink global after execution, whereas native sources call ChatFrameUtil.InsertLink and require a consumed return. It also had no resolved-item preview/required-cache validation.

The old drop input consisted solely of an edit-box OnReceiveDrag handler. It had no explicit cursor-item slot, click-to-place path, cursor location fallback or instrumentation. The new controls cover those native interaction paths and reject non-item cursors without clearing them. Terminal source inspection cannot establish which event the user's earlier drag actually delivered; the exact live event/focus failure must be checked in tests B/C.

The old PvP field had no explicit click focus, keyboard/enabled configuration, focus diagnostics or Enter handling, and the whole window registered for dragging. Worse, Save required a hyphenated identity and the old normalizer removed spaces. The repair scopes window dragging to the title bar, raises the editor/inputs above sibling content, explicitly wires focus and enabled behavior, accepts the native two-part name and removes the invalid identity requirement. **The precise live reason that the previous field would not type is not proven from terminal mocks.** It would be misleading to claim a confirmed mouse/focus root cause without running that widget inside WoW.

## Data/network changes

Schema 2 migration remaps old IDs and references while retaining requests, claims, decisions, history, ignored matches, UI preferences and position. Unrecoverable compressed names remain unresolved instead of receiving invented components. Old guild data is retained until the guild context becomes available; no raw obsolete identity fields are carried into the new object schema. Migration is idempotent.

Protocol GBF2 avoids mixing incompatible identity models. It carries context and keeps creator and claimant authority separate. Snapshots relayed by guild peers still rely on guild trust. Observations enrich local target resolution without allowing another player to modify the creator's entered target. Claims transport the actual kill evidence for the creator's review.

Loot uses both localized self-loot chat and bag-total increases. Stack formats are matched before single-item formats; positional quantity placeholders are supported. A persistent request/item suppression key prevents duplicate chat/bag prompts. Bag moves that do not increase totals are ignored. A trade/mail acquisition is labelled an inventory increase rather than falsely called loot.
